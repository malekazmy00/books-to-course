- **السبب:** ملاحظة المالك على النسخة الأولى من قائد الخط (`2daa94f`). كانت تخالف القرارات في ثلاث نقاط:
  1. توقف الخط عند رفض بوابة.
  2. بحث المعرفة يجري بعد الترجمة.
  3. الصوت يخرج كتلة واحدة للكتاب.
- **الحالة:** تحليل وخطة. لا تغيير في الكود في هذا الملف.

## 1. الترتيب الصحيح (D-034، D-035، learning-companion §11–§12)

```
الاستخراج v2 ← المخطط v2
  ← بحث المعرفة (EN، قبل الترجمة): المؤلف، والسياق، والتلقي، والمفاهيم في مجالها
  ← طبقة المفاهيم (EN)
  ← القاموس: المقابلات العربية المعروفة (Wikidata، وUNTERM، وArabTerm...) + تصويت النماذج (D-050)
  ← ترجمة الكتاب، ثم ترجمة كل الإثراء بالقاموس نفسه (D-035)
  ← بحث اللغة (AR، بعد الترجمة): المصطلحات غير المحسومة، والمواضع المتعثرة، وتصير حواشي
  ← الأشكال (EN ثم AR) ← نصوص الحلقات (EN ثم AR)
  ← الصوت حلقةً حلقة ← MP3 لكل حلقة (D-038، D-042، D-044)
```

## 4. ترتيب التنفيذ المقترح

1. **إزالة كل توقف من `CoursePipelineWorkflow`:** كل رفض يصير علامة أو حاشية ويستمر الخط، ويسجل التقرير ما تحوّل وأين.
2. **إعادة الترتيب:**
   - prepare للوحدات، ثم بحث المعرفة وطبقة المفاهيم، ثم القاموس مع المقابلات المعروفة، ثم الترجمة.
   - بعد الترجمة: ترجمة الإثراء، ثم بحث اللغة.
3. **الصوت حلقةً حلقة:**
   - `GenerateSpeechV2Input.episode_ar_ref`، وprepare يبني بـ `build_episode_speech_text`.
   - مسار لكل حلقة (أو أكثر بحد الـ 1800 ث)، ثم `EncodeEpisodeMp3Workflow` بأسماء 00..n.
4. **الاستخراج:** متابعة رغم رفض البوابة، مع علامات الجودة من `page_findings` إلى الوحدات والحواشي.
5. **بحث اللغة (AR):** بناؤه، فهو غير موجود.
